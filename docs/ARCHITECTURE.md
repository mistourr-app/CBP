# Архитектура

Как устроен проект и что делать, чтобы добавить в него новое.

---

## 1. Слои

Зависимости идут только сверху вниз:

```
ui  →  render  →  game  →  core  →  balance
```

| Слой | Что делает | Знает про |
|---|---|---|
| `balance.js` | Все числа игры | ничего |
| `core/` | Генератор с сидом, сохранение, шина событий, PWA | balance |
| `game/` | Правила: состояние, экономика, события, выборы, хроника | core, balance |
| `render/` | Трёхмерный город и окружение | game, balance |
| `ui/` | Интерфейс | game, render |

### Главное правило

**`js/game/**` и `js/balance.js` не знают про DOM и про Three.js.**

Из этого следует всё остальное:

- игровую логику можно запускать прямо в Node — поэтому тесты не требуют
  браузера и какой-либо сборки;
- симуляцию на сотни ходов можно прогнать в одну строку;
- 3D можно заменить на что угодно, не трогая правила.

Нарушение этого правила — повод не принимать изменение.

---

## 2. Правило «ни одной магической цифры»

Все числовые значения игры лежат в `js/balance.js`. В остальных файлах
чисел нет.

Это не формальность. В прототипе стоимость здания была записана в трёх
местах: при списании, при проверке «показывать ли кнопку» и при блокировке
кнопки. Правка одного места не трогала два других, и игра считала
неправильные суммы.

Чтобы проверить, что правило не нарушено, ищите в `js/game`, `js/render`
и `js/ui` числа, не взятые из `BALANCE`.

Исключения — оформление (`styles/*.css`) и внутренние константы
алгоритмов: индексы клавиш, размер сетки города `CELL`, шаг разбиения
диапазона. Всё, что игрок видит и чем чувствует, обязано быть в `balance`.

## 3. Поток хода

```
Игрок жмёт кнопку
        ↓
App.#takeTurn()                    js/ui/app.js
        ↓ блокирует кнопки
Session.takeTurn(id)               js/game/session.js
        ↓
Engine.applyAction(id)             js/game/engine.js   ← списание ресурсов
        ↓
Chronicle.add()                    js/game/chronicle.js
        ↓
Engine.advanceDay()                js/game/engine.js
        ↓
GameState.normalize()              js/game/state.js    ← согласованность
        ↓
Session.refreshChoices()           → Choices + bus
        ↓
Session.save()
        ↓
шина событий → StatsPanel, ChroniclePanel, ChoicesPanel, рендер
```

Интерфейс не вызывает движок напрямую. Он отправляет команду в сессию и
реагирует на события. Благодаря этому интерфейс можно переписать целиком,
не трогая правила.

## 4. Порядок внутри дня

Задан в `Engine.advanceDay()` и влияет на баланс, поэтому менять его нужно
осознанно.

| # | Шаг | Зачем |
|---|---|---|
| 1 | День вперёд, смена сезона | календарь |
| 2 | Назначение рабочих | новые здания сразу дают продукцию |
| 3 | Потребление: еда, обслуживание, спад счастья | цена дня |
| 4 | Производство | доход дня |
| 5 | Прирост населения | новосёлы, если есть место и еда |
| 6 | Повторное назначение рабочих | вчерашние новосёлы работают с завтрашнего дня |
| 7 | Событие дня | случайность |
| 8 | Условия окончания партии | итог |

## 5. Детерминированная случайность

Всё случайное идёт через `core/rng.js`, а не через `Math.random()`.

Сид хранится в партии. Одинаковый сид даёт одинаковую партию — это нужно
для симуляций и для тестов.

```js
const session = new Session();
session.rng.restore({ seed: 42, calls: 0 });

for (let i = 0; i < 500; i += 1) {
  session.takeTurn('wait');
}
```

Обращение к `Math.random()` в `js/game` и `js/render` — повод не
принимать изменение. В 3D свой отдельный генератор: расход чисел на
деревья не должен сдвигать случайность игры.

## 6. Как добавить здание

1. **balance.js** → `buildings.<key>`:
   ```js
   bakery: {
     name: 'Пекарня',
     actionLabel: 'Построить пекарню',
     icon: '🥖',
     cost: { gold: 60, wood: 25 },
     workers: 2,
     produces: { food: 8 },
     maintenance: 0.4,
     unlock: { buildings: { farms: 2 } },
     onBuild: {},
   },
   ```
2. **balance.js** → `choices.priority`: добавить `'build:bakery'` в нужное
   место списка. Без этого действие не попадёт в выборы.
3. **render/city.js** → `defineModels()`: описать внешний вид.

Больше ничего трогать не нужно: интерфейс, хроника, расчёты и панель
ресурсов подхватят здание сами.

---

## 7. Как добавить событие

1. **balance.js** → `events.definitions.<id>`:
   ```js
   locusts: {
     name: 'Нашествие саранчи', icon: '🦗', kind: 'disaster',
     minPopulation: 25,
     foodLossPct: 0.4,
     happinessLoss: 10,
   },
   ```
2. **balance.js** → `choices.priority` не нужен: событие не действие.
3. **game/events.js** → ветка `case 'locusts':` в `trigger()`.
4. **tests/sim.test.js** — партия должна пережить событие.

Вид события задаётся условиями в `availableEvents()`: поpopulation, по
сезону, по счастью, по наличию зданий или технологий.

---

## 8. Как добавить технологию

1. **balance.js** → `technologies.<key>` с `cost` и `requiresBuilding`.
2. **balance.js** → `choices.priority`: `'develop:<key>'`.
3. Указать эффект одним из полей: `productionMult` (множитель ресурса),
   `happinessPerWorker` (счастье за рабочего), `lossMult` (меньше потерь).
4. Прочитать эффект в `js/game/economy.js` или `js/game/events.js`.

Технология без эффекта — мёртвый сток ресурсов. Если эффект ещё не
придуман, не добавляйте технологию.

## 9. Слои 3D

| Модуль | Отвечает за |
|---|---|
| `render/index.js` | Сборка сцены, цикл отрисовки, пауза на скрытой вкладке |
| `render/scene.js` | Рендерер, камера, свет, небо, цикл суток, тени |
| `render/city.js` | Раскладка зданий по сетке, геометрия, instancing |
| `render/environment.js` | Земля, река, холмы, деревья, облака, снег |
| `render/palette.js` | Цвета по времени суток и сезонам |

### Раскладка города

`CityLayout` выдаёт клетки по спирали от центра и **запоминает место
каждого здания навсегда**. Это принципиально: если пересчитывать позиции
заново, постройка одной фермы сдвинет все дома, и игрок увидит, как
квартал переползает.

Здания одного типа рисуются одним `InstancedMesh`. Части здания (стены,
крыша, окна) склеиваются в одну геометрию, а их цвета переносятся в
**вершинные цвета** — иначе всё здание получило бы цвет первой части.

При пересоздании сетки из-за роста матрицы ранее построенных зданий
переносятся в новую.

### Если WebGL недоступен

`render/index.js` проверяет поддержку и возвращает пустой контроллер. Игра
продолжает работать без 3D-фона. Раньше падение `THREE` роняло всё
приложение, включая текстовую часть.

## 10. Сохранения

Ключ `cbp.save.v2` в localStorage. Внутри — `schema` из
`BALANCE.meta.schema`.

Правила:

- формат изменился → старое сохранение отбрасывается, партия начинается
  заново. Полусломанное состояние хуже чистого старта;
- `GameState.restore()` никогда не доверяет файлу: чинит занятость,
  ограничивает счастье, отбрасывает NaN;
- партия сохраняется после каждого хода.

Изменили формат состояния — поднимите `schema` и удалите старые сохранения
(см. `LEGACY_KEYS` в `core/save.js`).

## 11. Service Worker

Регистрируется в `core/pwa.js`, сам — `sw.js` на верхнем уровне.

- пути **относительные**: проект публикуется из подпапки `/CBP/`, и
  абсолютные пути не находили бы файлы;
- навигация — сначала сеть, при ошибке кэш: иначе игрок навсегда застревал
  бы в первой загруженной версии;
- статика — сначала кэш, обновление в фоне.

**При добавлении нового файла в `js/` или `styles/` допишите его в
`PRECACHE` в `sw.js`** — иначе офлайн не найдёт файл.

## 12. Тесты

```bash
npm test
```

| Файл | Что проверяет |
|---|---|
| `tests/economy.test.js` | Производство, потребление, обслуживание, население, склонения, защита от NaN |
| `tests/choices.test.js` | Четыре слота, «Подождать», доступность, достижимость всех зданий |
| `tests/save.test.js` | Версия схемы, отбраковка битых данных, детерминизм генератора |
| `tests/sim.test.js` | Партия на 500 ходов: без NaN, без минусов, партия доходит до конца |
| `tests/city.test.js` | Раскладка, отсутствие наложений, геометрия, освобождение ресурсов |

Тесты симуляции ловят то, что не видно без запуска в браузере: ошибки
раскладки и утечки ресурсов видеокарты проявляются только при большом
городе.

Правило: **новое поведение — новый тест.** Иначе оно вернётся.

### Проверка запуска

Юнит-тесты выполняют логику в Node и **не видят ошибок сборки**: обращения
к несуществующему методу, потеря `this` при передаче ссылки на метод,
падение при создании WebGL-контекста. Именно так игра падала при первом
открытии.

```bash
npm run serve:start    # сначала сервер
npm run check:boot     # затем проверка
```

`scripts/check-boot.js` открывает `scripts/boot-check.html` в headless-браузере:
игра загружается, создаёт WebGL-контекст, играет ходы, проверяются
инварианты состояния и рост населения. Браузер ищется автоматически
(Edge, Chrome, Chromium); путь можно задать переменной `BROWSER`.

**Запускайте её после изменений в `js/render/**` и `js/ui/**`** — именно
там ошибки не видны юнит-тестам.

## 13. Локальный сервер

`serve.js` — статический сервер на встроенном `http`, без зависимостей.
`serve-ctl.js` управляет его копией в фоне.

| Команда | Действие |
|---|---|
| `npm start` | Запуск в текущем терминале |
| `npm run serve:start` | Запуск в фоне, отсоединённый от терминала |
| `npm run serve:status` | Проверка процесса и порта |
| `npm run serve:restart` | Остановка и запуск |
| `npm run serve:stop` | Остановка |

Сервер создан с расчётом на постоянную работу:

- **занятый порт** (например, `TIME_WAIT` после быстрого перезапуска)
  приводит к повтору с паузой, а не к падению;
- **ошибка запроса** логируется и не трогает процесс;
- **грязный URL** и выход за пределы корня отдают 404, а не исключение;
- **проверка `HEAD`** не открывает файл;
- `Cache-Control: no-cache`: правка файла видна после обновления страницы,
  перезапускать сервер для этого не нужно.

Идентификатор процесса лежит в `serve.pid` (в `.gitignore`), логи — в
`serve.log` и `serve.err.log`. Файл PID очищается сам при остановке.

**При добавлении нового файла в `js/` или `styles/` допишите его в
`PRECACHE` в `sw.js`** — иначе офлайн не найдёт файл.
