# Город

Choice-driven симулятор города: один ход — один день, четыре варианта
действия, последствия видно в 3D.

Игра работает в браузере, ставится как приложение и запускается без
интернета после первого открытия.

---

## Запуск

Нужен [Node.js](https://nodejs.org) 18 или новее. Зависимости **не
устанавливаются** — их у проекта нет.

```bash
npm start                # http://127.0.0.1:8000 в текущем терминале
npm test                 # 81 тест на встроенном раннере Node
npm run check:boot       # проверка запуска в настоящем браузере
```

`check:boot` открывает игру в headless-браузере и проверяет, что она
загружается, создаёт WebGL-контекст, играет ходы и не падает. Нужен
запущенный сервер. Если браузер не найден, проверка молча пропускается.

Открывать файл через `file://` нельзя: браузер запрещает ES-модули и
Service Worker для локальных файлов. Нужен сервер — `npm start` или любой
другой статический.

### Сервер в фоне

Фоновый сервер отсоединяется от терминала и продолжает работать, пока вы
работаете в другом окне.

```bash
npm run serve:start     # запустить в фоне
npm run serve:status    # проверить, работает ли
npm run serve:restart   # перезапустить
npm run serve:stop      # остановить
```

Адрес по умолчанию — http://127.0.0.1:8000, другой порт задаётся через
`PORT=9000 npm run serve:start`. Идентификатор процесса пишется в
`serve.pid`, логи — в `serve.log` и `serve.err.log`.

Практические детали:

- **Перезапуск для правок не нужен.** Отдаётся `Cache-Control: no-cache`,
  поэтому после сохранения файла достаточно обновить страницу.
- **Сервер не падает от помех.** Занятый порт, битый запрос или ошибка
  чтения файла не завершают процесс: занятый порт — повтор с паузой,
  остальное — отчёт в лог.
- `npm run start:watch` перезапускает сервер при изменении самого
  `serve.js`.

Если нужно освободить порт, который держит мёртвый процесс, удалите
`serve.pid` и выполните `npm run serve:start`.

## Как играть

Каждый ход — один день. Игроку показываются четыре действия, он выбирает
одно. Дальше день идёт сам: расходуется еда, здания производят ресурсы,
случаются события, прибывают или уходят жители.

| Показатель | Что значит |
|---|---|
| 👥 | Население и лимит, который задают дома |
| 😊 | Счастье. Падает на единицу в день |
| 👷 | Сколько жителей занято на производстве |
| 🍞🪵🪨 | Еда и строительные материалы |
| 💰 | Золото: обслуживание, строительство, торговля |
| ✝️🧠 | Расходуются на технологии |

**Клавиши 1–4** — выбор действия на десктопе.

### Победа и поражение

- **Победа:** население от 100, храмов не меньше трёх, рынков не меньше трёх.
- **Поражение:** не осталось жителей, счастье упало до нуля или закончилась еда.

### Как играть, а не проигрывать

Главная сложность — **счастье**. Оно падает на единицу в день, а растёт
только от домов при постройке и от храмов с технологией «Религия»
(по единице за рабочего в храме). Без храмов город неизбежно теряет
народ примерно за 80 дней.

Порядок, который работает:

1. **Ферма** — без еды не живёт ни одна ферма.
2. **Лесопилка и карьер** — без них нет ни домов, ни храмов.
3. **Дома** — каждый добавляет 5 мест для жителей.
4. **Храмы → «Религия»** — якорь счастья.
5. **Рынки** — золото на обслуживание и торговлю.

Налогов нет: золото идёт только с рынков и торговли.

## Устройство проекта

```
js/
├── balance.js      все числа игры
├── core/           генератор с сидом, сохранение, шина событий, PWA
├── game/           правила: состояние, экономика, события, выборы, хроника
├── render/         3D: сцена, город, окружение, палитра
└── ui/             интерфейс
```

Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Правило проекта: **ни одной «магической» цифры** вне `js/balance.js`.
Балансируется игра правкой одного файла.
